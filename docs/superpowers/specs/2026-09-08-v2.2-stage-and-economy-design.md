# v2.2.0 "Stage & Economy" — design spec

Date: 2026-09-08. Status: approved by author after a Claude+Gemini consensus round (11/11 theses accepted, 1 AGREED_WEAK on model tiers, gated by the self-review test below).

## 1. Goal

Bring the skill to a polished, announce-ready state without touching the frozen `code` preset or the R1+R2 hard cap. Two axes:

- **Economy** — cut model cost per run (explicit model tiers, two call cuts).
- **Stage** — close the remaining Moreno elements that fit in zero or one extra call (Spectator, Protagonist chair, role reversal as STEELMAN).

Non-goals (deferred, see ideas backlog in the author's vault): market-test preset as agents, fifth-chair wildcard, perspective-swap round, `--heat`, pre-mortem, panel pre-flight, PR digest, PROTOCOL.md extraction, `CONSENSUS_STRENGTH` rename (breaking → next major).

## 2. Model tiers

**Current:** SKILL.md Protocol · Model says "One apex model across all agents. Not Sonnet, not a mix." Role agents inherit the session model (Step 4 note: no `model` parameter passed). With a top-tier session model, 9 inherited agents per run is prohibitively expensive.

**New rule (Protocol · Model, reworded):** *One model family across all agents — no cross-vendor dialogue by default (that is `consensus-protocol`). Tiers may differ per role.* Default tier map:

| Agent | Tier | Why |
|---|---|---|
| `psychodrama-decomposer` | opus | thesis quality bounds everything downstream |
| `psychodrama-judge` | opus | synthesis, holism check, verdict |
| `psychodrama-skeptic` | opus | the adversarial core of the product |
| `psychodrama-outside-frame`, `psychodrama-transgressive` | opus | rare, must be weighty |
| `psychodrama-champion` (new, §5) | sonnet | advocacy in a fixed format |
| `psychodrama-optimizer`, `psychodrama-security`, `psychodrama-maintainability-advocate`, `psychodrama-resource-keeper` | sonnet | per-thesis vote in a fixed tagged format |
| Duel mode: Tailored Critic | opus | adversarial core |
| Duel mode: Champion | sonnet | advocacy |

**Mechanism:** tier is declared in each agent file's frontmatter (`model: opus` / `model: sonnet`). The orchestrator does not pass `model` unless the user sets `--model <opus|sonnet|haiku>`, which overrides every agent for that run (pass the `model` parameter on each Agent call). Duel-mode calls use the generic `subagent_type="claude"` today and have no agent file; for them the orchestrator passes `model` explicitly per the table (`opus` for the Tailored Critic, `sonnet` for the Champion). This is the one deliberate exception to "tier lives in frontmatter" — documented in Protocol · Model as such, so there are exactly two mechanisms and both are named in one place. No thin agent files are added for duels (no file zoo).

**Docs:** README cost block, SKILL.md Protocol · Model, Principles ("One apex model everywhere. Not Sonnet, not a mix." → "One model family; tiers per role as declared in agent frontmatter"), DESIGN.md Known limitations ("Every Opus agent is the same model" → family wording). AUDIT_BLOCK gains `tiers:` line listing the effective tier per agent.

## 3. Call cuts

**3a. Early-finalize single Judge call.** Today Step 5 (Judge Phase A, aggregate) and Step 8 (Judge Phase B+C, synthesize) are always two calls, even when Phase A finds no DISPUTED/NEEDS_CLARIFICATION theses. New: Step 5 prompt asks the Judge to *also* produce the full synthesis (Phase B+C) **if and only if** its own aggregation yields an empty `DISPUTED_THESES` and no early 🕊 summon is triggered. The orchestrator then skips Steps 6–8 and goes to Step 9 (figures check) with the synthesis in hand. If `DISPUTED_THESES` is non-empty, the Judge returns aggregation only and the flow is unchanged.

**Figures after a merged call.** The merged call leaves the run in exactly the state it is in today after Step 8 (synthesis done, figures not yet checked), so Step 9 runs unchanged. Confirmed from SKILL.md Step 9 (lines 707–769): end-of-run figures are appended verbatim by the orchestrator to the render and the VDR — "No second Judge pass" — so the merged call changes nothing downstream of Step 8. The only figure that enters a Judge prompt is the early 🕊 (REFRAME_CLUSTER), which by definition means the merge did not happen.

**3b. Targeted R2 roster.** Today Step 7 dispatches the full roster on `DISPUTED_THESES`. New: dispatch only roles that voted DISPUTED or NEEDS_CLARIFICATION on at least one thesis in `DISPUTED_THESES`, **plus always `Skeptic`** (Adversarial Presence invariant holds in R2). Roles not dispatched keep their R1 votes. The Step 8 Judge prompt (and the merged Step 5 prompt when relevant) gets an explicit structured line `R2_PARTICIPANTS: <role, role, …>` (or `R2_PARTICIPANTS: none`), so the Judge never infers participation from the vote text. `--roles` overrides still apply.

**Updated budget (panel):** 1 Decomposer + 4 votes + 1 Judge = **6 minimum** (true minimum today is 7: the README's "6" omits the second Judge call). With R2: + (1–4 re-votes) + 1 Judge = **8–10**, typical 8. Protagonist chair +1, figures +1–2, external critic +1. Duels unchanged: 9–13.

## 4. Spectator mode (`--spectator`)

A render option, zero extra calls. When set, the Judge's synthesize call (Step 8, or the merged Step 5 call) appends a `## Match report` section to the VDR:

- One block per thesis: who struck first and with what (must cite an actual R1 tag: ANCHOR/FLIP/CONDITION/REFRAME), who held, who flipped in R2 and after which argument (cite the STEELMAN or the opponent's FLIP), score line (e.g. `3:1 against`).
- `### Figures on stage` — if a figure appeared, one line: what it did to the frame.
- `### Minority report` — the losing position as a standalone paragraph (this promotes the existing minority-report content to a named section; the VDR keeps its own copy).
- `### One-line result` — a ≤ 25-word summary for sharing.

Guard against dramatization: every "hit" line must quote or reference a tag from the record; the Judge may not invent moves. Default off; the confirm line mentions `--spectator` as available.

## 5. Protagonist chair (`--position`, triage-detected)

**Triage addition (Step 0):** the orchestrator checks whether the question states the user's own stance (patterns: "I want to", "we decided", "I plan to", "my proposal is", RU equivalents "я хочу", "мы решили", "планирую"). If detected, the confirm line adds a soft offer, since the detector is a heuristic and may misfire: `Looks like you've stated a position: "<quote>". Give it the Protagonist chair, with a Champion to defend it? (+1 call; --position "<text>" / --no-position to force)`. A wrong detection therefore costs the user one "no", never a wasted call. Explicit `--position "<stance>"` forces on with that text; `--no-position` suppresses detection. No stance detected → no offer.

**Mechanics (panel mode only):**
- New agent `agents/psychodrama-champion.md` (sonnet): mandate — defend the Protagonist's stated position thesis by thesis, same vote format and tags as voters; must state on which theses the position is weakest (`WEAK_POINT:` tag, mandatory). Non-adversarial; does not satisfy Adversarial Presence; does not count toward the 3–7 roster size.
- R1: Champion dispatched in the same parallel batch as the roster. Voters receive one extra line in their prompt: `Protagonist position: "<stance>". Stress-test it explicitly where a thesis touches it.` The Skeptic additionally receives: `A Champion is defending the user's stated position. Your job includes preventing the panel from anchoring on it — vote on the theses, not on the Protagonist.` (anchoring guard).
- R2: Champion re-votes only if it was DISPUTED/NEEDS_CLARIFICATION on a thesis in `DISPUTED_THESES` (same rule as §3b).
- Judge: verdict gains a mandatory line `PROTAGONIST: survived | survived with conditions | did not survive — on theses <list>`. AUDIT_BLOCK gains `protagonist: <yes/no>`.
- Empty chair check (existing) still runs; the Protagonist's chair is not the empty chair.

Duel mode: no Protagonist chair (champions already exist per perspective). Triage in duels mode ignores the detection.

## 6. STEELMAN in R2 (role reversal, zero calls)

R2 prompt for every dispatched role: before the vote on each thesis in `DISPUTED_THESES`, the role must write one line `STEELMAN: <the strongest version of the opposing position, in the role's own words>`. Then the vote and rationale as today. The Judge treats a missing STEELMAN on a re-voted thesis as an invalid vote (same handling as a missing FLIP on DISPUTED): the vote is dropped from aggregation and noted in the record. README's Moreno table: "Role reversal (roadmap)" → "Role reversal — STEELMAN in R2 (v2.2)".

## 7. Market-test demo (no protocol change)

One real run, panel mode, on a product/pricing question, using existing ephemeral-persona syntax: `--roles "+cfo(focus:'...'),+end-user-therapist(focus:'...'),+procurement(focus:'...'),+client-security(focus:'...')"` with Skeptic kept for the invariant. Output saved as `examples/market-test-demo.md`, with a short maintainer's note on which personas held up. README "Composable panel" links to it as a non-engineering example. No new agents, no preset.

2. Check: every Sonnet voter rationale carries ANCHOR on every vote, FLIP on every DISPUTED, CONDITION where applicable; STEELMAN present on every R2 re-vote; PROTAGONIST line present; `R2_PARTICIPANTS` line present in the Judge prompt and reflected in the record; if the run finalized early, the single Judge output contains both the aggregation table and the full synthesis; the match report contains all four sections and every "hit" line references a tag that exists in the R1/R2 votes (spot-check every line — no invented moves).
